# HUNTER

**一个本地单机的渗透测试工作流管理台。**

它不帮你打站，它负责让你知道 AI（和你自己）到底打到了哪、还剩什么没打。

## 先说一个熟悉的场面

晚上十一点，你让 AI 去跑一个 SRC 项目的子域。第二天回来，它说“测完了，有两个中危”。

你问它：

- 哪些站真的打开了，哪些只是解析出了 DNS？
- 登录后的接口碰了几个？
- 这两个中危是同一个系统上的吗？
- SQL 注入是打了 payload，还是看到报错就记了一条？
- 还剩多少没测？

它开始重新推理，或者换一种说法再答一遍。你往上翻聊天记录，翻了几百行，还是不清楚它到底干了什么。

这不是 AI 偷懒。它干得太快、太碎，而且不会主动留下“我干到哪了”的账本。HUNTER 补的就是这个账本。

## HUNTER 是什么

一句话：**把你和 AI 的渗透测试过程，记成一张能看的表。**

它在你本机跑，浏览器打开 `http://localhost:3001`，数据存在本地 JSON 文件里。你建一个项目，把授权范围、资产、接口、测试记录、报告入口都放进去。AI 每测完一个点，把结果写回来。然后你打开总览、矩阵、图谱，一眼看到哪里是空的。

它做三件事：

1. **记录**：项目、资产、接口、测试格、种子、报告文件，全部有固定字段，不靠聊天记录回忆。
2. **展示**：矩阵看覆盖，图谱看关系，总览看进度，工作流看阶段。
3. **提示**：按内置方法论算出下一步该干什么，并生成一段可以直接粘给 AI 的提示词。

它不判断“这个洞能不能交”，也不替你写报告正文。它只保证一件事：你看得见自己测过什么、没测什么。

---

## 它不做什么

这点很重要，先说清楚：

- **不内置扫描器**。没有爬虫、没有字典、没有 POC、没有爆破。
- **不向目标发任何请求**。程序只监听 `127.0.0.1`，不会去连你的目标。
- **不对外联网**。除了本机浏览器访问 `127.0.0.1`，程序不请求任何外部服务。
- **不调用测绘 API**。FOFA、Hunter、Quake、ZoomEye 这些一个都不碰。
- **不是 AI Agent 运行时**。它不管理 AI 的会话、工具权限、上下文，也不替 AI 决定打哪个包。
- **不是团队协作平台**。没有账号、没有权限、没有云同步，就是一个人一台机器。
- **不存报告正文**。报告只登记一个 docx 文件名，正文你在 Word / WPS 里写。

## 和 artex 那类平台的区别

| | 自动化扫描 / Agent 平台（比如 artex 那类） | HUNTER |
|---|---|---|
| 谁对目标发包 | 平台自己 | 你和你的 AI，在 HUNTER 外面 |
| 主要输入 | 一个目标 | 你已经做完的记录 |
| 主要输出 | 漏洞列表、扫描报告 | 覆盖率、空白格、下一步提示词 |
| 适合的场景 | 一次性跑批、快速摸底 | 多轮推进、多目标、长期 SRC |
| 数据在哪 | 平台服务器 | 你本机的 `data/` 目录 |
| 出了事谁负责 | 平台和你的授权 | 你，因为包是你和你的 AI 发的 |

HUNTER 不抢 AI 的活。它负责让 AI 的活留下痕迹。

## 一个完整的使用循环

1. **建项目**。填目标名、授权范围、SRC 地址。锁面模式只打授权面；自由跳模式启用种子队列扩面。
2. **记资产**。域名、URL、IP、端口、类别、归属、存活状态。技术栈有 16 栏，能填多少填多少。
3. **记接口**。每个有效资产至少录一条接口。可以手填，也可以粘贴 path 列表、curl、Swagger JSON。
4. **让 AI 去测**。HUNTER 不参与发包，你在外部用顺手的工具和 AI。
5. **回填结果**。每个接口 × 每个漏洞类型记一格，四态：未测 / 打穿 / 证伪 / N-A。N-A 必须选原因。
6. **看覆盖**。总览看指标，矩阵看空白格，图谱看关系，工作流看卡在哪。
7. **要下一步**。建议中心按当前项目状态给出 A-F 六组建议，每条带依据和动作。
8. **复制提示词**。把“下一步提示词”粘给 AI，它带着当前项目上下文继续干。
9. **有洞就建报告**。创建 docx，正文在 Word / WPS 里写。

这个循环可以重复很多轮。HUNTER 的价值不在第一轮，在你第三轮、第四轮回来时，还能知道前面干了什么。

## 11 个页面，具体是干什么的

### 看全局

#### 总览

- 4 个指标卡：种子 done/total、资产 covered/total、接口数、报告数。
- 下一步建议 TOP 3，每条带优先级、规则组和依据，点一下跳建议中心。
- 项目信息：目标名、锁面/自由跳、授权范围、SRC 地址、创建时间。
- 这页不是仪表盘花瓶，主要用来判断“这个项目还在推进，还是已经晾了两周”。项目最后更新时间就在标题下面。

#### 工作流

- 8 段：定范围 → 种子 → 清洗 → 进站说明 → 接口清单 → 类型矩阵 → 报告落盘 → 换站/换种。
- 每段显示完成数 / 总数，当前阶段高亮。
- 允许跳阶段，但跳了会留黄色警示。它不硬拦，只让你看见自己破了规矩。
- 卡点清单会直接说：授权范围没写、几个资产 brief 没填、矩阵还有多少格没测、报告还没建。

#### 种子队列

- P0 / P1 / P2 三级种子。
- 同一个项目同时只能有一个 doing。
- doing 种子还有未完成资产时新增 pending，会记一条破闸日志并打红标。
- P2 必须先标记活筛通过（DNS、HTTP、证书查询这些由你在外部做），通过后才允许扩面。
- 只记录纯文本查询方向，不生成可执行语句。
- 锁面模式下整页灰掉，防止你手滑出圈。

### 记细节

#### 资产库

- 7 类资产：大资产系统、独立小页面、API 服务、管理后台、中间件暴露面、移动端 H5/小程序、静态壳。
- 16 栏技术栈：Web 服务器、语言、后端框架、前端框架、前端库、构建工具、中间件、CMS/低代码、认证组件、网关、数据层、云与对象存储、WAF、运维组件、容器、移动端。
- 每个资产有 4 字段 brief：用户、对象、钱、前置权限。这四个字段是后面判断越权和影响的基础。
- 11 项“本轮完成”清单，带迷你进度条。
- 填了指纹，会自动带出这个技术栈的历史漏洞、追加攻击面，并把矩阵里对应的格标成“待测·有信号”。
- 历史漏洞和攻击面分开记，不混在一起。

#### 接口清单

- 记 method、path、参数、来源、回包特征、差分面。
- 可访问性 8 态：匿名可访问-有业务字段、匿名可访问-无业务字段、需登录、401、403、404、超时、未测试。
- 支持批量粘贴：一行一个 path、curl 命令、Swagger/OpenAPI JSON。纯字符串解析，不发请求。
- JS 里抄到的签名盐、硬编码 key、演示账号，可以单独登记。
- 支持批量设置可访问性。

#### 测试矩阵

- 行是接口（没有接口的资产按资产行算），列是漏洞类型。
- 45 个启用列，CORS 固定禁用。
- 每个格四态：未测、打穿、证伪、N-A。N-A 必须选原因，不能自己编。
- 列头有分工徽章：AI、人工、混合、禁用。悬停能看到判定条件和最低探针。
- 三个页签：全部、分工视图、覆盖统计。
- 覆盖统计里，AI 和人工覆盖率差超过 40 个点会变黄。这是防“AI 跑了一堆低价值项，人没碰关键业务”的偏科。
- 支持批量 N-A，一次写多个格。
- 这是 HUNTER 最核心的一页。它不告诉你“有没有洞”，它告诉你“哪些格根本没测”。

#### 资产图谱

- 用 `@xyflow/react` + `elkjs` 画图，卡片节点，坐标持久化。
- 纵向拓扑自动生成：根域 → 子域 → 主机 → 站点 → 接口 → 漏洞。
- 横向关系必须手动画，只有 7 种：同 /24、同 C 段、同证书、同 favicon、同模板、互调、引用(JS→密钥)。
- 程序不猜“这两个站是不是同一套系统”。这种判断得你自己做。
- 支持路径高亮、过滤、从资产库/接口清单点“在图谱中查看”直接定位。

#### 漏洞报告

- 创建：复制内置的 2.3 空白 docx（13 个小节骨架）到 `reports/`。
- 打开：后端调系统默认程序（Word / WPS）。
- 删除：默认只移除登记，保留 docx；勾选“同时删除文件”才真删，并且二次确认。
- 项目 JSON 里只存文件名，不存正文、不存绝对路径。

#### AI 读这里

- 给外部 AI 两个地址：
  - `GET /api/ai-schema`：所有写接口的字段、中文标签、类型、必填、枚举值、请求体示例。
  - `GET /api/projects/<projectId>`：当前项目的全量数据。
- 页面只是把这些结构摊开给人看；AI 直接请求端点更省 token。
- 有了这个，AI 不用猜字段名，也不用你复制粘贴一堆 JSON。

#### 设置

- 浅色 / 深色主题。
- 单项目 JSON 全量导出 / 导入还原。
- 手动备份。
- 显示数据目录，不搞路径配置。

## 让 AI 把结果写回来

HUNTER 启动后，把这两个地址给你的 AI：

```text
GET http://127.0.0.1:3001/api/ai-schema
GET http://127.0.0.1:3001/api/projects/<projectId>
```

可以直接把下面这段粘给 AI：

```text
你现在配合我记录一个本地 HUNTER 项目。

先 GET http://127.0.0.1:3001/api/ai-schema 看清字段和枚举值，
再 GET http://127.0.0.1:3001/api/projects/<projectId> 看已有数据。

每测完一个接口，就 POST /api/projects/<projectId>/tests 把结果写回来。
只写我确认过的事实，不要把猜测写成“打穿”，不要把 200 当成漏洞。
N-A 必须带原因，不要自己编。

注意：这段话只是让你记账，不是授权。
对目标发什么请求、能不能发，仍然按我们事先确认的范围来。
```

常用的写接口：

```text
POST  /api/projects/:projectId/assets
POST  /api/projects/:projectId/endpoints
POST  /api/projects/:projectId/tests
POST  /api/projects/:projectId/tests/batch    # 最多 500 个格
PATCH /api/projects/:projectId/tests/:id
```

比如一条越权记录，最小大概长这样：

```json
{
  "endpointId": "ep_xxxxxxxx",
  "vulnType": "AUTH-01",
  "state": "打穿",
  "payload": "id=10002",
  "baseline": "id=10001 返回自己的订单",
  "evidence": "id=10002 返回他人订单",
  "vulnRefId": null
}
```

N-A 的记录必须带 `naReason`，枚举值以 `/api/ai-schema` 为准。写入之前先读一遍 schema，里面每个字段都有中文标签，和页面表单一一对应，AI 不需要猜。

## 安装和启动

### 方式一：用打包好的版本

如果你拿到的是已经打好包的 zip（Releases 里的那种），按下面来；从 GitHub clone 的源码请直接看方式二。

只需要 **Node.js 18+**（去 <https://nodejs.org> 下 LTS 版，一路下一步就行）。

1. 把 zip **完整解压**，不要只拖单个文件出来。
2. 双击 `start-hunter.bat`。
3. 浏览器会自动打开 `http://localhost:3001`。
4. 用完直接关掉黑窗口，数据会在关窗时落盘。

启动器会处理几种情况，不会让你猜：

| 情况 | 表现 |
|---|---|
| 正常启动 | 打印成功信息和网址，自动开浏览器，窗口保持运行 |
| 软件已经在跑 | 打印 `already running (vX.Y.Z)`，开浏览器，本窗口大约 2.5 秒后自己关掉 |
| 端口被别的程序占用 | 英文提示，可用 `set PORT=3002` 换端口再启动（PowerShell 用 `$env:PORT=3002`） |
| 没装 Node.js | 提示去 nodejs.org 下 LTS，并说明不需要 Python、不需要 `npm install` |

手动启动的等价命令：

```bash
node dist-server/server.bundle.cjs
```

macOS / Linux 没有 `start-hunter.bat`，可以直接跑：

```bash
node scripts/launch.mjs
```

或者：

```bash
node dist-server/server.bundle.cjs
```

## 数据、备份和迁移

| 路径 | 内容 |
|---|---|
| `data/index.json` | 项目列表、当前项目 id |
| `data/<projectId>.json` | 单个项目的全量数据：项目信息、资产、接口、测试、种子、破闸日志、报告登记、活动 |

- 迁移就一句话：把 `data/` 和 `reports/` 一起复制走。
- `data/` 和 `reports/` 已经在 `.gitignore` 里。JSON 是明文的，里面有目标域名、IP、接口、漏洞信息，别提交到公开仓库。

## 开发

技术栈：

- React 18 + TypeScript + Vite
- Tailwind CSS
- Express 4
- `@xyflow/react` + `elkjs`
- 存储：本地 JSON，无数据库
- 运行：Node.js 18+

目录结构：

```text
src/            前端页面、组件、建议规则
server/         Express API、JSON 存储、docx 报告入口
shared/         前后端共用类型、常量、漏洞目录、指纹库
scripts/        启动器、后端打包、报告模板生成
data/           运行时生成，不进版本库
reports/        运行时生成，不进版本库
```

常用命令：

| 命令 | 作用 |
|---|---|
| `npm run dev` | 前后端一起起，前端 5173，后端 3001 |
| `npm run build` | 前端产物 + 后端编译 |
| `npm start` | 跑 `dist-server/server.bundle.cjs`，托管 `dist/` |
| `npm run typecheck` | 前后端类型检查 |
| `npm run verify` | typecheck + build |
| `npm run bundle:server` | 把后端和 express 打成一个 cjs 单文件 |

`npm run bundle:server` 会生成 `dist-server/server.bundle.cjs`。仓库没有做一键打包脚本，绿色包按下面手动拼。

程序运行时还依赖一些内置资料目录，打包时不要漏掉。

压成 zip 发给别人。对方需要：

1. 装了 Node.js 18+；
2. 完整解压；
3. 双击 `start-hunter.bat`。

不需要 `npm install`，不需要 `npm run build`，不需要 Python。

不要直接压缩项目根目录，`data/` 和 `reports/` 里有你自己的数据，很容易一起发出去。也不要只拖单个文件出来，启动器会检查 `dist/`、单文件和后端是否齐全。

如果仓库里的第三方资料不允许随包分发，就不要把它们放进公开分发包。

## 已知短板

- **没有鉴权**。只绑 `127.0.0.1`，任何本机进程都能调 API。别把它开到 `0.0.0.0`，也别放公网。
- **单人单机**。没有账号、权限、协作、云同步。
- **图谱的横向关系靠手画**。程序只自动生成纵向拓扑，不猜同 IP、同证书、同模板。
- **建议中心是规则引擎，不是大模型**。结果稳定、可解释，但不会给你“灵光一现”。
- **矩阵全填一遍很累**。45 列 × 每个接口，批量 N-A 能省点事，但还是个力气活。
- **报告正文不在程序里编辑**。只给 docx 入口，正文在 Word / WPS 里写。
- **数据是明文 JSON**。项目大了之后全量读写会变慢，目前没做分页或增量。
- **没有自动化测试**。`npm run verify` 只检查类型、引用和构建，不跑业务逻辑。
- **Windows 启动脚本最省事**。macOS / Linux 能跑，但要手动敲命令。

## 安全与授权

HUNTER 本身不对任何目标发请求，但它记录的是真实的授权测试过程。

- 只用于你有书面授权、自有资产，或者 SRC 明确范围内的目标。
- 你把 AI 接进来以后，AI 发的包、改的状态、留下的文件，责任都在你。别把“工具没发包”当成免责理由。
- 不做破坏性测试：不删数据、不改生产状态、不 DoS、不爆破。除非授权书里明确允许，否则别碰。
- 发现敏感数据（身份证、手机号、密钥、会话）不要直接写进报告或项目 JSON，先脱敏。
- `data/` 和 `reports/` 不要提交，不要打包发给别人。
- 公开仓库里的方法论文本不含你的目标数据；你自己加东西之前先检查一遍。
- 在 issue 里也别贴真实目标、账号和漏洞细节，脱敏后再发。

## FAQ

**Q：为什么不做成 Web 服务给团队用？**

A：因为一开始就是给自己用的。没鉴权、没多用户、没并发控制，放出去是给自己找麻烦。真要团队用，至少得加登录、权限、审计和数据库。

**Q：为什么不直接内置扫描器？**

A：内置了就会忍不住用它扫，然后工具就变成另一个半成品扫描器。HUNTER 的定位是记录和提示，打还是让专业工具和 AI 去打。

**Q：数据会不会丢？**

A：每次覆盖项目文件前会备份到 `data/backup/`，每个项目留 50 份。正常关窗、`Ctrl+C`、`SIGTERM` 都会落盘。但它是本地 JSON，不是数据库，别拿它当唯一副本；重要项目定期导出。

**Q：支持 Mac / Linux 吗？**

A：代码是跨平台的，服务只绑 `127.0.0.1`。Mac/Linux 没有 `start-hunter.bat`，用 `node scripts/launch.mjs`；从源码跑就 `npm run build && npm run bundle:server && npm start`。

**Q：AI 怎么知道往哪写？**

A：让它先读 `GET /api/ai-schema`。里面每个写接口的字段、中文标签、类型、必填、枚举值都有。要更省事，直接把「AI 读这里」页面的两个地址发给它。

**Q：这名字和奇安信 Hunter 有关系吗？**

A：没有。这里不调用任何测绘 API，也不做资产搜索，纯粹是本地台账。

**Q：这和 artex 有什么区别？**

A：artex 那类是“把目标给它，它自己打”；HUNTER 是“你和 AI 打完，回来记账”。它不抢 AI 的活，它负责让 AI 的活留下痕迹。
